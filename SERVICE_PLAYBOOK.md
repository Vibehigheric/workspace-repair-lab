## Intake checklist (private channel)

Ask for OS/tool versions, exact redacted error, what changed, expected behavior, project size, admin restrictions, backup status and permitted downtime. Agree what commands may run. Ask for no passwords, tokens, private keys or complete environment dumps. Customer handles all authentication. Use a written authorization for access and changes.

## Offer services on GitHub appropriately

GitHub permits project-related promotional text and links in a repository README or project description, but the primary content must not be advertising. Do not advertise in other people's issues, harvest contacts, send unsolicited bulk messages, automate stars, or claim affiliation with maintainers.

Use a substantive tool repository with this demonstration, a short related-services section, and an approved external inquiry link. Pin the repository on your profile. A profile README can describe skills and link to your real work, without invented certifications or customer results. This is a portfolio channel, not a promise of customer leads.
